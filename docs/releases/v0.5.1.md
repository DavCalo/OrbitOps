# OrbitOps v0.5.1 — correctness hardening

OrbitOps v0.5.1 is a focused correctness patch. It fixes two known numeric/runtime defects without
adding product capability or changing serialized compatibility contracts.

## Fixed

- The C++ thermal scenario now validates fixed-width telemetry values before narrowing conversion.
  Sequence `419` remains representable; if generation reaches sequence `420`, the simulator fails
  closed before encoding or transmitting an invalid temperature instead of allowing wraparound or
  sign inversion.
- Python telemetry encoding now rejects booleans and other non-integer values for integer-valued
  packet fields while preserving valid integer ranges and existing range errors.
- `LinkRuntime.run(max_packets=...)` now accepts only `None` or valid integer packet counts, rejecting
  booleans and other non-integer values explicitly while preserving the existing positive-integer
  domain.

## Compatibility

- The binary telemetry protocol remains version `1` with the same byte layout.
- Telemetry recording remains version `1`.
- Mission-profile and alarm-policy schemas remain version `1`.
- Link-event emission remains schema version `2`, with schema-version-1 reading preserved.
- Alarm-event schema remains version `1`.
- Session reports remain `orbitops.session_report/v1`.
- Existing valid Python numeric inputs remain supported.
- CLI syntax and serialized JSONL/report contracts are unchanged.
- Thermal runs that reach an unrepresentable generated value now fail non-zero before packet
  emission; this is the intentional correctness change for the affected invalid runtime boundary.

## Validation

The release candidate is required to pass the repository's complete `make verify` gate, all C++
scenario/boundary regression tests, supported Python 3.11–3.13 compatibility jobs, Linux/macOS C++
builds, sanitizer checks, package-resource checks, and fresh installed-wheel package/session checks.

The retained v0.5.0 benchmark and 60-minute soak files remain reference evidence and are verified by
checksum for this patch release. They are not reinterpreted as a v0.5.1 performance measurement,
performance SLA, leak-free guarantee, or general reliability certification.

An additional external usability walkthrough is not required for v0.5.1 because the correctness
fixes do not materially change the documented onboarding or operator workflow.

## Supported environment

- Python 3.11–3.13;
- C++17;
- CMake 3.20 or newer;
- Linux and macOS for the supported CI/build paths.

## Known boundaries

OrbitOps remains technical-preview simulation software. UDP transport is unauthenticated and
unencrypted; CRC-32 and configuration fingerprints are not cryptographic authenticity or provenance
mechanisms. The project is not flight software, a safety-certified alarm system, an RF propagation
model, or a claim of CCSDS compliance.
